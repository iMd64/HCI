SLIDE 03 (PART 1) • 1. LATENCY > 0.1 S

The system responds, but too slowly

Even small delays break the illusion of immediacy. Consider the mobile “New Message” (“Meeting at 3?”) tap scenario:

Step 1: User taps “Send” 0 ms
Send 👆

User presses the blue Send button to send “Meeting at 3?”

Step 2: No immediate feedback ~300–800 ms
⟳ (Silent wait)

Interface stays silent or delays visible acknowledgment.

Step 3: System finally responds ~800–1500 ms
✓ Message sent

Consequence: User may tap again → Duplicate actions (multiple emails, multiple payments), frustration, loss of trust.

SLIDE 04 • WHY IMMEDIATE FEEDBACK MATTERS

When the interface stays silent, users act twice.

1. Tap The user presses a button.
2. No Feedback No color change, animation, or vibration. “Maybe it didn't work?”
3. Tap Again The user assumes it failed and presses again.

What is happening? (HCI Responsiveness): The first tap may already be registered, but the user receives no visible or tactile acknowledgment. The brain interprets silence as failure. So the user repeats the action to “make sure.”

What can go wrong?: Duplicate actions • User confusion • Loss of trust • Error cascades.

Key Idea (Slide 04)

“No feedback becomes perceived failure.”

Design Rule (100 ms)

A system should acknowledge input immediately — ideally within 100 ms — through color change, animation, sound, vibration, or a loading indicator.

SLIDE 07 SLIDE 08 • Path Dependence & The Speed vs. Learnability Trade-off
SLIDE 07 • THE POWER OF PATH DEPENDENCE (TECHNOLOGICAL INERTIA) 1872 Mechanical Layout → 2024 Glass Screen

Why do we use a 19th-century mechanical layout on 21st-century glass screens?

The QWERTY layout survives through installed habit. Once a standard is in place, the vested interests of existing practices impede change—even when mechanical constraints no longer exist.

SLIDES 07 & 08 • KEYBOARD PARADIGMS COMPARISON
Keyboard System Speed / Performance Cognitive & Adoption Reality
1. QWERTY Layout (Slide 07, 1872–2024) Standard baseline (50–80 WPM on physical keys) Survives through Path Dependence & installed habit. Learned by millions worldwide.
2. Dvorak Layout (Slide 08) 10–15% speed improvement and reduced finger travel Fails due to the massive legacy knowledge of QWERTY. “The ergonomic gain is not worth the cognitive pain.”
3. Chord Keyboards (e.g., Microwriter / Court Stenographer Model, Slide 08) Simultaneous keypresses generate entire syllables or full words; Extreme speeds (>300 WPM) Steepest learning curve: requires all knowledge to be held in the user's head (recall vs. recognition).
SLIDES 09–14 • Soft Keyboards, Lost Physical Affordances & Algorithmic Compensation
SLIDES 09 & 10 • PHYSICAL KEYBOARD 50–80 WPM

Rich Physical Affordances

  • • Keys have edges: Finger can feel where one key ends and the next begins (Slide 11).
  • • Resistance is felt: The key pushes back, so the body senses the action.
  • • Tactile feedback: The user knows a press happened without looking.
  • • No-look operation: Fingers orient by touch; body continues typing while attention is elsewhere.
SLIDES 09 & 10 • GLASS SCREEN (SOFT KEYBOARD) 35–40 WPM

The Hardware Deficit

  • • No key edges: Soft keyboards lack physical edges, destroying tactile feedback.
  • • No physical resistance: Flat glass surface provides zero mechanical pushback.
  • • Finger can slide: Tactile boundary is missing.
  • • Teaching point (Slide 10): Mobile typing is not merely a “small keyboard” problem. It is a physical affordance problem.
SLIDE 11 • CORE LAW OF GLASS INPUT

Hardware support decreases → Software intelligence must increase  |  Physical affordance → Algorithmic compensation

SLIDES 09 & 12 • WORD-GESTURE TYPING

A Path, Not Perfect Taps

The user draws an approximate path; the algorithm infers the intended word:

1. Capture path: The finger movement becomes a trace.
2. Compare patterns: The path is compared with possible words.
3. Use language model: Common words and context resolve ambiguity.
4. Output intent: The system writes the most likely word.

✔ Burden shifts: from precise human motor control → to algorithmic interpretation.

SLIDES 18–23 • The Physics of the UI: Fitts's Law & The Edge Effect ★ Core Exam Formula
SLIDES 18 & 19 • FITTS'S LAW FORMULA & MOVEMENT ECONOMY

Fitts's Law

Time to acquire a target is a function of the distance to it and its size. Design is not only about looks; it is also about movement economy.

T = a + b log2(2D / W)
D = Distance to the target
(Larger D → Slower)
W = Width of the target
(Larger W → Faster)
• Near + Large = FAST (High-frequency actions like Send should be large and easy to reach — Slide 21).
• Far + Small = SLOW (Low-frequency or dangerous actions can be smaller or farther — Slide 21).
SLIDES 18–20 • TARGET ACQUISITION & THE EDGE EFFECT
The Edge Effect (Slides 18 & 20): Screen edges and corners behave like “infinitely wide” targets because the pointer cannot move past the screen edge—the edge stops the cursor physically. Examples: Menu bars, Corner buttons, Hot corners / dock areas.
SLIDES 24–31 • Buxton's 3-State Model, Hover & Ergonomic Tax
SLIDE 24 • BUXTON'S 3-STATE MODEL

Sensory-Motor States of Input Devices

William Buxton's model captures the sensory-motor distinctions between input devices by mapping which physical states they can inhabit.

0

State 0: Out of Range

(Device is not tracked by the system)

1

State 1: Tracking (Hover)

(Device moves the cursor / hover state, no action taken)

2

State 2: Dragging / Engaged

(Button depressed / screen touched, action is occurring)

SLIDES 26 & 30 • APPLYING THE 3-STATE MODEL TO DEVICES (EXAM COMPARISON)

Touchscreen

State 0–1 Device

• Finger off screen = 0 (System does not know exact position).
• Finger touching screen = 1 (Action begins immediately).
• There is no 'hover' state — no safe "preview" stage before action.

Mouse

State 1–2 Device

• Moving on desk = State 1 (Tracking).
• Button clicked/dragged = State 2 (Engaged).
• Always tracked while on the desk. Cannot easily be 'out of range' (State 0).

Light Pen / Stylus

State 0–1–2 Device

• Lifted far away = 0.
• Hovering above screen = 1 (Hover).
• Touching screen = 2 (Action).
• Allows the richest interaction vocabulary.

SLIDES 25, 27–29 • WHY HOVER MATTERS: 1. APPROACH → 2. HOVER → 3. ACT

Hover gives the user a safe step between “seeing” and “acting.” Without hover, the user must commit immediately. With hover, the user can first position, preview, and confirm.

SLIDE 27 • 4 CONCRETE EXAMPLES OF HOVER
  • • Small button selection: Hover helps the user check the target before pressing.
  • • Drawing / illustration: The pen cursor shows where the stroke will start.
  • • Tooltip / preview: The system can reveal more information before click.
  • • Menu navigation: The user can explore options without committing yet.

Simple summary: Hover lowers risk before action.

SLIDE 28 • WHAT DOES THE HUMAN GAIN? (5 GAINS)
1. Preview: See before you commit
2. Precision: Place pointer accurately
3. Error reduction: Avoid wrong clicks/strokes
4. Confidence: Feel safer before action

SLIDE 31 • THE HUMAN COST OF INPUT (PHYSIOLOGICAL FATIGUE)

1. Repetitive Strain Injury (RSI)

Tendons control finger movement. Overuse through unnatural, repeated keystrokes causes inflammation and Carpal Tunnel.

2. Gorilla Arm

The primary reason vertical touchscreens (like desktop monitors) fail. Lifting the arm to point at a vertical screen requires continuous shoulder tension, leading to rapid muscle fatigue.

SLIDES 32–35 • Implicit Input Sensors & Error Recovery

The Rise of Implicit Input

Interaction is moving from explicit commands (clicking a button) to incidental / implicit interaction (the system sensing your context). The device translates physical world signals into digital state changes without the user ever pressing a key (Slide 32).

1. PROXIMITY SENSOR

Phone to the ear

Detects when the phone is held to the face, turning off the screen automatically to prevent accidental touches.

2. GPS / SPEED / MOVEMENT

Driving mode

Detects geographic location and speed/movement without explicit data entry; switches phone to driving mode.

3. ACCELEROMETER & GYROSCOPE

Raise wrist to wake

Detects rotation, tilt, and motion (physical orientation); wakes up the watch with a wrist movement.

SLIDES 34 & 35 • WHAT IF THE SYSTEM GUESSES WRONG? Example failure: Phone thinks you are driving, but you are a passenger!

Good HCI does not only guess intent; it also makes recovery easy. Rule: Automation should be helpful, but never trap the user.

1. Visible status Immediately see what mode the system entered (e.g., Driving mode: Auto-reply active).
2. Easy override Simple manual way to turn it off (Turn Off button).
3. Undo / cancel If the guess caused an unwanted action, reverse it easily.
4. Settings / control Reduce, disable, or tune the automation when needed.
SLIDES 37–43 • The Interface Vanishes (3 Pillars of Input Hardware)

What Does “The Interface Vanishes” Mean?

The ultimate goal of HCI hardware is to lower the barrier between human intention and digital action until the translator feels invisible (Slide 37). The interface vanishes when the user stops thinking about the tool and focuses on the task (Slide 38).

✘ Visible Interface (Friction & Confusion — Slide 38–39)

User thinks: “Where is the button? What should I do next?”

If the user has to fight the interface, the interface has not vanished.

✔ Vanished Interface (Transparent Translator — Slide 38–39)

User thinks: “I am doing my task.” The tool feels natural.

Pipeline: Human intent → Physical action → Input device → Digital action → Task completed

SLIDES 36 & 44–50 • Context-Matching Diagnostic Framework ★ Complete 4-Scenario Synthesis

Context-Matching Diagnostic Framework

There is no universally superior input device. Design is entirely dictated by user context, task, body, environment, and cost of error.

Scenario Dominant Constraint Ideal Input Solution Real Examples & Design Moves Why Not Other Inputs?
1. Precision Pixel Work (CAD / Editing) (Slides 36, 46, 50) Extreme accuracy needed. Small errors are costly. Indirect + Absolute/Relative (Mouse / pen tablet / stylus) Examples: CAD handles, pixel image editing, vector paths, timeline handles.
Moves: Cursor pointing, zoom + fine control, stable targets, hover & preview. 		Finger touch causes occlusion; fat-finger problem reduces precision; voice cannot express spatial detail.

Moves: Large clear buttons, minimal steps, high contrast, physical numeric keypad. 		Mouse unfamiliar standing up; stylus gets lost/damaged; complex gestures hard to learn; voice fails in noisy public spaces.

SLIDES 51–56 • Part 2: Output Devices & The Sensory Translation

Output is the Computer's Voice

Output devices are deliberate translations of invisible digital states into human sensory stimuli. Stop asking “What can the machine display?” and start asking “What can the human perceive?” (Slide 56).

SLIDE 52 • 1. RIGHT CHANNEL

Visual, audio, or haptic?

The system must use a sensory channel the user can perceive in that context.

SLIDE 52 • 2. RIGHT TIME

Too late = too weak

Even correct feedback can fail if it arrives after the user needed it.

SLIDE 52 • 3. RIGHT INTENSITY

Too little or too much

Strong enough to notice, but not so strong that it overloads the user.

SLIDES 57–70 • Channel One: Sight (Spatial vs. Temporal Perception & Display Matrix)
SLIDES 58–61, 64–65 • 1. SPATIAL PERCEPTION

WHERE do we see detail best?

• Foveal Vision (~2° viewing angle): Sharp center used for accurate reading (e.g., Vehicle Dashboard Speed 65 in readable center display — Slide 59).
• Peripheral Vision: Blurry wide field sensitive to motion and contrast changes (e.g., Lane alert peripheral light/vibration — Slide 59, or a red notification badge Inbox 3 — Slide 61).
• Web Placement Trap (Slide 60): Main content area gets attention, while low-contrast tiny corner text / terms in a low-attention corner is missed.

SLIDES 62–69 • 2. TEMPORAL PERCEPTION (REFRESH RATE)

HOW smoothly do we see change?

• Mechanism (Slide 63): Displays redraw the screen sequentially, line by line.
• Flicker Perception: Refreshing at 60 to 120 Hz (times per second) is required to trick the human visual system into perceiving fluid animation and preventing eye-fatiguing flicker.
• Application: High refresh rates are critical for rapid, direct manipulation (dragging windows, smooth scrolling) without ghosting or smearing.

30 Hz ● ● ● ● More gaps / jerky
60 Hz ●●●●●●●● Smoother motion
120 Hz ━━━━━━━━━━● Fluid / zero ghosting

SLIDES 71–78 • Channel Two: Sound & Channel Three: Touch (The Haptic Duality)
SLIDES 71–74 • CHANNEL TWO: SOUND — THE 360-DEGREE AMBIENT CHANNEL

The Auditory Advantage & Non-Speech Audio Spectrum

1. Omnidirectional

Unlike vision, hearing does not require spatial focus. We receive auditory info from any direction.

2. Auditory Adaptation

The brain processes background sounds passively, ignoring them until they change or cease (e.g., a fan stopping).

3. Eyes-Free & Hands-Busy

Mandatory output channel when visual attention is fully consumed (driving, surgery, walking).

SLIDES 73 & 74 • THE NON-SPEECH AUDIO SPECTRUM

Core Concept: Speech requires high attention. Non-speech sounds communicate complex system states in a fraction of a second with minimal cognitive load.

🎵 Earcons

Abstract

• Definition: Abstract, synthetic, musical tones.
• Cognitive Cost: Requires learning (arbitrary mapping).

🗑️ Auditory Icons

Concrete / Literal

• Definition: Literal, natural, everyday sounds representing objects/actions.
• Mechanism: Instant recognition based on real-world physics.
• Classic Example (SonicFinder — Slide 74): Folder makes a rustling papery noise; throwing a file in the wastebasket triggers the sound of smashing glass.

SLIDES 75–78 • CHANNEL THREE: TOUCH — THE HAPTIC DUALITY

Cutaneous (Tactile) vs. Kinesthetic (Proprioceptive)

Dimension 1. Cutaneous (Tactile) — Slides 76 & 77 2. Kinesthetic (Proprioceptive) — Slides 76 & 78
Biology Mediated by thermoreceptors (temperature) and mechanoreceptors (pressure) in the skin. Mediated by receptors in the joints and muscles detailing the position and movement of limbs.
Sensation Vibration, texture, surface pressure. Resistance, weight, spatial force.
Hardware Taptic engines, vibration motors, electronic Braille displays. Force-feedback steering wheels, robotic medical controllers.
Real-World Applications
• Micro-confirmations (Slide 77): Phone vibration on digital keypress replaces lost mechanical button feel, improving typing confidence.
• Primary Output Channel (Slide 77): For deafblind users, an 8-pin electronic Braille display translates on-screen text into rapid skin indentations.
• Simulated Resistance (Slide 78): Force feedback calculates physics of virtual objects and applies motor resistance.
• Sensory-Motor Training: Wearable actuators (MusicJacket) give vibrotactile “nudges” to correct a violin player's bowing posture.
• Medical Simulation: Surgeons “feel” resistances of virtual tissue types before real operations.

SLIDES 84 & 85 • THE 3 CONSTANTS OF HUMAN PSYCHOLOGICAL TIME
0.1s (100 ms)

Causality, Flinch Reflex, Perceptual Motor Feedback

System Requirement: Instant action acknowledgment; smooth animation (>10 fps).

1.0s (1000 ms)

Conversational Gap Limit

System Requirement: Limit of uninterrupted wait time. Requires a busy indicator if exceeded.

10.0s

Unit Task / Attention Span Limit

System Requirement: Requires background routing and percent-done progress bars.

SLIDE 85 • THE 100-MILLISECOND DEADLINE (CAUSALITY GAP)

50ms vs. 150ms & The 10ms Stylus Ink Rule

• Design Rule: Onscreen buttons have exactly 0.1 seconds (100ms) to show they have been clicked.
• Electronic Ink Rule: Electronic ink must never lag the stylus by more than 10ms.

● Feedback at 50ms:
Brain registers: “I caused this.”
● Feedback at 150ms:
Brain registers: “Misclick. Try again.”
SLIDE 86 • ICON WARS

Cursor Tracking & Icon Wars

  1. 1. The Delay: User clicks icon. System freezes for 800ms.
  2. 2. The Buffer Queue: User clicks 3 more times, hits 'Enter', presses 'Escape'. System silently queues inputs.
  3. 3. Icon Wars: CPU catches up; screen explodes in a chaotic burst of unintended actions.

Result: Post-completion errors and unpredictable states.

SLIDE 87 • THE ART OF THE FAKE

Designing for Delays

  • • Track A — Rubberbanding: Instead of rendering a heavy 3D sphere at 5 fps, draw a lightweight bounding box moving at 60fps to preserve hand-eye coordination.
  • • Track B — Progressive Rendering: Show a low-res image instantly and progressively sharpen it.

Rule: Buy the system an extra second by giving the user something to look at immediately.

SLIDE 88 • 1.0S TO 10.0S RULES

Filling the Void (Progress Bars)

✘ THE DON'T (iMovie Busy Bar) Striped bar violates >1.0s rule: no time clue, no way to abort.
✔ THE DO (Mac OS X Transfer) Shows 11.9 MB of 38.9 MB + [Cancel] button: maintains conversational protocol, gives time estimate, lets user switch unit task.
SLIDES 79–82 & 89–94 • Multimodal Synthesis, Cognitive Load & Accessibility
SLIDES 80, 82 & 89 • THE MULTIMODAL SAFETY NET & DISTRIBUTING COGNITIVE LOAD

Distributing Information Across Sensory Channels

Distributing information across multiple sensory channels ensures the message survives even if one channel is overwhelmed (Slide 80).

✘ Route A: Visual Only (Slide 89)

Primary Task: Driving a Car (High Visual Load)

GPS displays a complex visual map → Visual channel interference causes critical failure.

✔ Route B: Multimodal Bypass (Slides 80 & 89)

Auditory + Haptic Bypass

• Auditory Channel: Voice navigation says “Turn left”.
• Haptic Channel: Steering wheel vibrates for lane departure (even if loud music compromises audio!).
• NASA-TLX (Task Load Index) Insight (Slide 89): Multimodal routing actively lowers mental demand, temporal demand, and user frustration by utilizing modality-specific interference rules.

SLIDE 90 • THE MULTITASKING MYTH

Multitasking is actually rapid attention-switching

Heavy Multitaskers High Cognitive Tax

High attention switching tax, slow reaction times, easily distracted.

Light Multitaskers Low Cognitive Tax

Efficient allocation of attention, faster task completion.

Multimodal interfaces should reduce the need to switch attention, not encourage users to consume five media streams at once.

SLIDES 81 & 91 • MULTIMODAL ARCHITECTURE & CURB-CUT EFFECT

Richness vs. Redundancy

Path A: Richness (Expert Workflow — Slide 91): A power user holds 'Shift', drags a mouse, and speaks a command simultaneously. Fusing multiple channels exponentially increases human bandwidth and speed.
Path B: Redundancy (Universal Design — Slide 91): Visual text is duplicated aloud by a Screen Reader, and color-coded alerts are paired with distinct audio pitches for visually impaired users.
The Curb-Cut Effect (Slides 81 & 91): “Solve for one, extend to many.” Features built for severe disabilities benefit everyone (e.g., sidewalk curb cuts help wheelchairs, strollers & carts; Closed Captions [CC] engineered for the deaf are heavily used by mobile users watching video in public on mute).

SLIDE 93 • SUMMARY: THE ORCHESTRATED INTERFACE

1. Sync the Tempo

Match system feedback to the strict 0.1s, 1.0s, and 10.0s psychological time constants.

2. Route the Traffic

Offload cognitive demand from the easily congested visual cortex by routing alerts to auditory and haptic channels.

3. Embrace Constraints

Design systems that rely on sensory redundancy to gracefully survive environmental friction and accessibility challenges.

“You are not designing screens. You are orchestrating human attention across time and sense.”
